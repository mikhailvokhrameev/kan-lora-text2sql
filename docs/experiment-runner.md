# Запуск эксперимента и карточка результата

`scripts/run_experiment.py` читает YAML и принимает `--method`, `--dataset`,
`--seed`, `--run-kind`, `--train-subset`, `--eval-limit`, `--config` и `--output`. Методы:
`lora`, `dora`, `kan_lora` и `none`. Последний означает базовую модель без
адаптера и обучения; оценка проводится тем же путём. Пример полного прогона:

```sh
python scripts/run_experiment.py --config configs/base.yaml --method kan_lora --dataset spider --seed 0
```

Каждый запуск получает уникальный идентификатор и резервирует каталог
`results/v2/{run_kind}/{run_id}/` до загрузки модели и обучения. Повторное
резервирование существующего каталога вызывает ошибку и не меняет его.
Все методы получают одинаковые данные, зерно, гиперпараметры, fp32 и протокол
оценки. После внедрения адаптера цикл обучается на подвыборке, валидируется
на отложенной части обучающих данных, затем выполняется жадная генерация и
расчёт Exact Match и Execution Accuracy. EA вычисляется на полном dev по одной базе на пример. Все базы и эталоны
проверяются до загрузки модели: final и pilot останавливаются при ошибке,
а smoke сохраняет EA как `null` с причиной в `execution_accuracy_reason`.
При успехе причина равна `null`. PAUQ использует собственные базы.

Карточка `card.json` схемы v2 содержит идентификатор, конфигурацию,
происхождение, метрики, размеры модели, время, пик памяти, функции потерь и
нормы градиентов. Пути `artifacts` относительны к каталогу прогона:
`predictions.jsonl` содержит индекс исходного dev, db_id, gold_sql и
predicted_sql, а `adapter.pt` содержит обучаемые тензоры адаптера и
конфигурацию. У `method: none` checkpoint и поля обучения отсутствуют или
равны `null`. После успешной записи артефактов карточка публикуется атомарно;
её наличие означает завершённый прогон. Каталог без `card.json` — прерванный
прогон; автоматически он не удаляется и не перезаписывается. Таблицы читают
только завершённые каталоги v2; старые карточки отклоняются. Методически
несовместимые результаты нельзя смешивать.

Удаление Muon, измерения задержки, диагностики сетки и абляции CLI сокращает
матрицу исследования. Это методическое решение: существующие результаты
прежней матрицы не следует смешивать с новыми; затронутые ячейки необходимо
пересчитать перед сравнением. Для проверки кода достаточно unit-тестов с
крошечной моделью, без запуска полномасштабных экспериментов.

### Режим и происхождение

`--run-kind` переопределяет значение YAML и принимает `smoke`, `pilot` или `final`; в базовой конфигурации
выбран final, в проверочной — smoke. Final требует чистое относительно HEAD
отслеживаемое дерево git, seed 0, GTX 1080 Ti (sm_61), полный непустой dev
без `eval_limit`. Неотслеживаемые файлы на проверку чистоты не влияют.
В smoke и pilot состояние дерева также сохраняется в карточке. До обучения
загружаются модель и токенизатор с одним полным SHA `model_revision`, и их
фактические ревизии проверяются на совпадение с конфигурацией. Ревизия взята
из локального snapshot Hugging Face, а не из подвижной ветки.

Поле `provenance` содержит конфигурацию, версии, HEAD, состояние
отслеживаемых файлов, индексы, хэши входов, устройство, название GPU, compute capability и фактические флаги
`deterministic_algorithms`, `cudnn.deterministic`, `cudnn.benchmark`. Эти
флаги не гарантируют побитовое совпадение между платформами. Отсутствующая SQLite в происхождении записывается как null; для final и
pilot проверка данных при этом останавливает прогон. Изменение фиксации модели и входов требует
перезапуска всех затронутых ячеек итоговой матрицы.

Карточка сохраняет коммит встроенного Spider evaluator и SHA-256 файла `uv.lock`
в provenance. Таблица требует эти поля и хэши использованных оценочных файлов.

Итоговая матрица использует seed обучения 0; seed можно задать явно для
воспроизведения. Сравнение методов выполняется при одном rank и общих
условиях, без выравнивания числа параметров; число параметров приводится
рядом с метриками. Различия Spider и PAUQ не являются чистым эффектом языка.
