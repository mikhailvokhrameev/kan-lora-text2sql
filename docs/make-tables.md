# Сборка таблиц и графиков (`scripts/make_tables.py`)

**Модуль:** `scripts/make_tables.py`
**Тесты:** `tests/test_make_tables.py`

## Зачем таблицы собираются скриптом, а не пишутся руками

Единица поставки экспериментов — карточка результата (`docs/experiment-
runner.md`, `results/*.json`). Если числа в тексте работы переносить в
таблицы руками, любое число становится невосстановимым из карточек: нельзя
проверить, откуда оно взялось, и легко ошибиться при копировании. Скрипт
читает все карточки из каталога и одной командой строит `results/tables.md`
и `results/figures/fraction_inside_grid.png` — заново, целиком, при каждом
запуске.

## `load_cards`

```python
def load_cards(directory: Path) -> list[dict]
```

Читает все файлы `*.json` из каталога (сортировка по имени файла — для
воспроизводимого порядка строк в таблицах) и разбирает их как JSON. Формат
карточки не проверяется схемой — он зафиксирован в `results.py`
(`build_result_card`), и здесь предполагается уже валидным.

## `aggregate`

```python
def aggregate(cards: list[dict]) -> dict[tuple[str, str], dict[str, tuple[float, float] | None]]
```

Группирует карточки по ключу `(method, dataset)` и для каждой метрики даёт
пару `(среднее, размах)` по зёрнам.

Размах (`max - min`), а не стандартное отклонение — при трёх зёрнах (0, 1, 2
из глобальных ограничений плана) оценка отклонения статистически
неустойчива, а размах прямо отвечает на вопрос «насколько далеко разъезжаются
прогоны одного метода». Выводы в тексте работы формулируются только по
различиям, выходящим за этот размах: ожидаемая разница между методами по
Exact Match — порядка одного-двух процентов, то есть внутри разброса по
случайному зерну.

Значения `None` (не число) исключаются из усреднения до деления, а не
заменяются нулём: Execution Accuracy на PAUQ может быть `null` при
отсутствии файлов баз данных (`docs/execution.md`), и «не мерили» обязано
остаться отличимым от «получили ноль». Если после фильтрации не осталось ни
одного значения, ячейка получает `None` целиком, а не `(0.0, 0.0)`.

Помимо метрик (`exact_match`, `execution_accuracy`) в тот же агрегат
попадают `peak_memory_bytes` и `trainable_parameters` — они нужны основной
таблице, а по построению карточки одинаковы для всех зёрен одного метода на
одном наборе, поэтому их среднее и размах не публикуются отдельно.

## `main_table`

```python
def main_table(cards: list[dict]) -> str
```

Строит таблицу Markdown: одна строка на пару «метод, набор», отсортированную
лексикографически. Метод и набор выводятся значениями конфигурации
(`lora`, `dora`, `kan_lora`, `spider`, `pauq`) без перевода в
«красивые» подписи — таблица собирается из тех же строк, что и `run_id`
карточек, и не вносит собственного словаря соответствий, который расходился
бы с конфигурацией при добавлении нового метода.

Первая строка таблицы — плейсхолдер «без адаптера (базовый уровень)» с
текстом-заглушкой вместо чисел. Он обязателен методологически: без строки
базового уровня (модель без адаптера) невозможно ответить на вопрос «что
дала адаптация вообще», а не только «какой из трёх методов адаптации
лучше». Скрипт не заполняет эту строку сам — карточка результата для
базовой модели пока не производится ни одним прогоном, — а оставляет её
как обязательное место для заполнения в тексте работы.

Каждая ячейка метрики выводится функцией `_cell` в виде `среднее ± размах/2`
(например, `0.4200 ± 0.0200`) или строкой «не измерялась», если для этой
пары «метод, набор» ни одно зерно не дало значения.

## `nonlinearity_table` и `optimizer_table`

```python
def nonlinearity_table(cards: list[dict]) -> str
def optimizer_table(cards: list[dict]) -> str
```

В отличие от `main_table`, обе таблицы построены по отдельным прогонам
(`run_id`), а не агрегированы по зерну — они раскрывают величины, которые
имеет смысл смотреть по каждому прогону отдельно, а не усреднять.

`nonlinearity_table` берёт `spline_stats` карточки (сводка
`analysis/spline_stats.py`, `docs/nonlinearity.md`: индекс нелинейности —
доля необъяснённой дисперсии при подгонке прямой к функции ребра сплайна) и
для каждого прогона выводит средний и максимальный индекс по всем адаптерам
модели, а также последнее значение `fraction_inside_grid` — долю активаций
сплайна внутри сетки к концу обучения. Карточки без `spline_stats` (LoRA,
DoRA — они не нелинейны, поле равно `null`) пропускаются, а не выводятся
строкой из прочерков.

`optimizer_table` берёт `optimizer_coverage` карточки — распределение
обучаемых параметров между `torch.optim.AdamW` и `torch.optim.Muon`
(`docs/optimizers.md`) — и выводит абсолютные числа и долю параметров,
пришедшихся на Muon. При нулевом суммарном числе параметров в обоих
оптимизаторах (не должно происходить на реальных карточках, но карточка не
проверяется схемой на входе) строка выводится с нулями и прочерком в доле,
без деления на ноль.

Ветка «сумма параметров равна нулю» оформлена как обычный `if total: ... else:
...` на двух строках, а не как тернарное выражение внутри f-строки. Более
компактная запись через тернарное выражение здесь читается неоднозначно:
условие `if total else` синтаксически привязывается к результату всего
`f"..."`, а не к числителю доли, из-за чего вся строка целиком (включая уже
подставленные `muon` и `adamw`) выглядит так, будто зависит от `total`, хотя
фактически заменяется только последний столбец.

## `plot_fraction_inside_grid`

```python
def plot_fraction_inside_grid(cards: list[dict], path: Path) -> None
```

Строит график `fraction_inside_grid` по эпохам, по одной линии на прогон, у
которого это поле не пусто (для LoRA и DoRA список пуст — линия не рисуется).
Ось Y ограничена `[0.0, 1.05]`: величина по определению не превышает 1.0, а
небольшой отступ сверху не даёт точкам у значения 1.0 сливаться с верхней
рамкой графика. Легенда добавляется только если на графике есть хотя бы одна
линия — на пустом входе `plt.legend()` печатает предупреждение в лог без
дополнительной проверки.

Рисование идёт через backend `Agg` (`matplotlib.use("Agg")` до импорта
`pyplot`), заданный до первого импорта `matplotlib.pyplot` — без этого на
машине без дисплея (в том числе в CI и на машине обучения без X11) выбор
интерактивного backend по умолчанию может завершиться ошибкой при попытке
открыть окно.

## `main` и формат вывода

```python
def main() -> int
```

Аргументы командной строки: `--results` (каталог с карточками, по умолчанию
`results`) и `--output` (каталог для `tables.md` и `figures/`, по умолчанию
тот же `results`). Если каталог с карточками пуст, скрипт печатает сообщение
и возвращает код 1, не создавая пустых `tables.md` — таблица без единой
строки была бы легко спутана с таблицей, которая просто не пересобрана после
изменений.

При наличии карточек в `results/tables.md` последовательно пишутся три
раздела — основная матрица, нелинейность, покрытие Muon — и создаётся
`results/figures/fraction_inside_grid.png`. Оба пути создаются заново при
каждом запуске (`Path.mkdir(parents=True, exist_ok=True)`), а не
дозаписываются: файл `tables.md` — не журнал, а снимок текущего набора
карточек.

## Проверенные инварианты

- `load_cards` читает ровно те карточки, что лежат в каталоге, независимо от
  числа файлов (`test_loads_every_card`).
- `aggregate` даёт среднее и размах по зёрнам, совпадающие с ручным расчётом
  на трёх карточках одного метода (`test_aggregate_reports_mean_and_spread`);
  для единственного зерна размах равен нулю
  (`test_single_seed_has_zero_spread`).
- Отсутствующая Execution Accuracy (`None`) не превращается в ноль при
  усреднении, а даёт `None` целиком для всей пары «метод, набор»
  (`test_absent_execution_accuracy_does_not_become_zero`).
- `main_table` показывает размах рядом со средним (символ `±`), включает
  обе сравниваемые в тесте пары «метод, набор» и является таблицей Markdown,
  а не текстом без разметки (`test_main_table_shows_spread_next_to_the_mean`),
  и всегда содержит строку-плейсхолдер базового уровня без адаптера
  (`test_main_table_includes_the_baseline_row_placeholder`).
- `optimizer_table` показывает покрытие и Muon, и AdamW
  (`test_optimizer_table_shows_muon_coverage`).
- `plot_fraction_inside_grid` создаёт непустой файл графика
  (`test_plot_writes_a_file`).

## Не реализовано

Строка «без адаптера (базовый уровень)» в основной таблице всегда
плейсхолдер — прогон базовой модели без адаптера (нужен, чтобы показать
эффект адаптации как таковой, а не только различие между тремя методами
адаптации) отдельным типом карточки не производится. Замер фактического
времени прогона и запуск полной матрицы экспериментов на GTX 1080 Ti (задача
19 плана) — ещё не сделаны; до них `results/*.json` пусты и
`python scripts/make_tables.py` возвращает код 1.
