# Мера выученной нелинейности (`analysis/spline_stats.py`)

**Модуль:** `src/kanlora/analysis/spline_stats.py`
**Тесты:** `tests/analysis/test_spline_stats.py`

## Зачем эта мера нужна

Это не техническая, а исследовательская часть работы. Главный вопрос,
ради которого весь стенд строится: **использует ли KAN-LoRA нелинейность
сплайна на самом деле, и какой ценой** (KAN-LoRA не умеет сливаться с
весами — см. [`adapters.md`](adapters.md) — поэтому нелинейность,
если она не используется, оплачивается задержкой генерации без всякой
пользы).

Измерение прямое: к каждой выученной одномерной функции ребра сплайна
подгоняется прямая методом наименьших квадратов на том отрезке, куда
реально попадают активации и где при этом определён сплайн (см. «Область
измерения»), и берётся доля дисперсии, которую эта прямая не объясняет. Индекс, равный нулю по всем рёбрам всех адаптеров, —
доказанный отрицательный результат («нелинейность не используется, метод
сводится к LoRA с накладными расходами»), а не признак неудачной
реализации.

## Область измерения

B-сплайновый базис определён только на сетке `grid_range` (по умолчанию
`(-1, 1)`), за её пределами все базисные функции равны нулю и сплайн
возвращает ноль (см. [`adapters.md`](adapters.md)). Слой считает
`out = s * phi(x / s)`, где `s` — `input_scale` соответствующего входа,
поэтому сетка лежит в координате `u = x / s`, а в координатах входа `x` это
отрезок `grid_range * s` (при отрицательном `s` границы меняются местами;
`s` берётся с тем же полом на модуль, что и в `forward`).

Если подгонять прямую на отрезке, выходящем за эту область, часть выборки
приходится на нулевой «хвост» сплайна, и индекс измеряет не выученную
функцию, а обрыв на границе сетки: даже тождественный, необученный слой на
отрезке `[-3, 3]` получал индекс около 0.81. Поэтому отрезок измерения для
каждого входа — **пересечение запрошенного отрезка с областью определения
сетки в координатах входа**. Доля входов вне сетки при этом не теряется:
она публикуется отдельно как `fraction_inside_grid`.

Детали:

- Область берётся с запасом `0.99` от краёв (`0.99 * grid_range * s`):
  базис полуоткрыт, и в самой правой точке сетки он уже равен нулю.
- `input_scale` у каждого входа свой, поэтому и отрезок обрезается отдельно
  для каждого входа `source`, а не одним общим.
- Если пересечение пусто или вырождено в точку (`start >= stop`),
  измерять нечего: рёбра такого входа не попадают в результат
  `layer_nonlinearity`. Если так вышло со всеми входами адаптера,
  `mean` и `max` в `model_nonlinearity` равны `NaN` — это сигнал «все
  активации вне сетки» (его подтверждает `fraction_inside_grid`), а не нуль.
- Математика адаптера (базис, инициализация, семантика `input_scale`) не
  менялась: это поправка только измерения. Ранее записанные значения
  `spline_stats` (в том числе в смоук-карточках) считались без обрезки и
  с ней несравнимы.

## `nonlinearity_index`

```python
def nonlinearity_index(inputs: torch.Tensor, outputs: torch.Tensor) -> float
```

Считает

```
index = RSS / TSS,
```

где `TSS` — полная дисперсия `outputs` относительно среднего, а `RSS` —
остаточная сумма квадратов после подгонки прямой `outputs ≈ a * inputs + b`
методом наименьших квадратов (`torch.linalg.lstsq` на паре признаков
`[inputs, 1]`). Значение зажимается в `[0.0, 1.0]`: `0.0` — функция и есть
прямая (или её частный случай — константа), `1.0` — прямая не объясняет
ничего (например, симметричная относительно нуля парабола на симметричном
отрезке, где наилучшая прямая вырождается в константу).

Подгонка и сумма выполняются в `float64` независимо от входного типа —
величина используется как диагностика с претензией на точность, а не как
часть градиентного пути, поэтому дороговизна двойной точности здесь не
имеет значения.

Отдельно обработан вырожденный случай `TSS ≈ 0` (постоянная функция):
вместо деления на ноль возвращается `0.0`, потому что константа — частный
случай прямой, а не неопределённость.

## `layer_nonlinearity` и `EdgeStats`

```python
@dataclass(frozen=True)
class EdgeStats:
    source: int
    target: int
    nonlinearity: float

def layer_nonlinearity(layer: KANLayer, lo: float, hi: float, samples: int = 257) -> list[EdgeStats]
def measurement_interval(layer: KANLayer, source: int, lo: float, hi: float) -> tuple[float, float] | None
```

`KANLayer` (см. [`adapters.md`](adapters.md)) — это `in_features x
out_features` независимых одномерных функций, по одной на каждое ребро
графа Колмогорова — Арнольда. `layer_nonlinearity` перебирает все рёбра:
для каждого входного индекса `source` подаёт на слой пробный батч, где
координата `source` пробегает равномерную сетку `[lo, hi]` из `samples`
точек на отрезке `measurement_interval(layer, source, lo, hi)` (см.
«Область измерения»), а все остальные координаты — нули, и снимает отклик по каждому
выходному индексу `target`. Обнуление остальных координат не искажает
измерение: базисные функции слоя действуют покоординатно, поэтому отклик
на ребре `(source, target)` не зависит от значений на других входных
координатах.

Отрезок `[lo, hi]` — обязательный внешний параметр, а не константа сетки
сплайна: измерять нужно там, куда реально попадают активации на
отложенном наборе, а не на всей области определения. `model_nonlinearity`
берёт этот отрезок из фактического размаха входов, накопленного каждым
адаптером (см. ниже). Допустимы `lo = -inf`, `hi = inf` — тогда мерится вся
область определения сетки; так `model_nonlinearity` поступает, когда через
адаптер ещё не прошло ни одного батча. Сверх того отрезок всегда обрезается
по области определения сетки.

Результат — список `EdgeStats` длиной `in_features * out_features` (меньше —
если для каких-то входов пересечение с сеткой пусто, их рёбра пропускаются), без
фиксированного порядка обхода за пределами вложенных циклов по `source`
и `target`; тесты используют его как множество пар `(source, target)`, а
не как последовательность.

## `model_nonlinearity`

```python
def model_nonlinearity(
    model: torch.nn.Module, ranges: dict[str, tuple[float, float]] | None = None
) -> dict[str, dict[str, float]]
```

Сводка по всей модели, ключ — полное имя адаптера из `adapter_modules`
(`kanlora.adapters.inject`, см. [`adapters.md`](adapters.md)). Не-KAN
адаптеры (`LoRALinear`, `DoRALinear`) в сводку не попадают вообще — у них
нет обучаемой нелинейности, и пустой словарь для чисто линейного метода
(`{}`) — это осмысленный, а не ошибочный ответ.

Отрезок измерения `[lo, hi]` для каждого адаптера выбирается в таком
порядке:

1. `ranges[name]`, если вызывающий код его передал — без собственных
   проверок (обрезка по сетке всё равно выполняется в `layer_nonlinearity`).
   Так `scripts/run_experiment.py` мог бы передать
   отрезок, вычисленный по всей отложенной выборке разом, а не только по
   тому, что случайно прошло через адаптер на предыдущих вызовах.
2. Иначе — `module.observed_range()` (см. [`adapters.md`](adapters.md)):
   фактический размах `A x`, накопленный адаптером за все прямые проходы с
   момента его создания.
3. Если и он ещё пуст (`observed_lo > observed_hi`, то есть ни одного
   прохода не было), — `(-inf, inf)`, то есть вся область определения сетки.

Выбранный отрезок затем обрезается по сетке отдельно для каждого входа
(см. «Область измерения»).

Для каждого `KANLoRALinear` собирается:

- `mean` — среднее значение `nonlinearity_index` по всем измеренным рёбрам
  слоя;
- `max` — максимум по тем же рёбрам (один вырожденный сплайн не должен
  теряться в усреднении по семи проекциям каждого слоя трансформера);
  `mean` и `max` равны `NaN`, если ни одно ребро не измерено (весь размах
  вне сетки);
- `fraction_inside_grid` — `module.mean_fraction_inside_grid()`, средняя
  доля активаций, попавших в сетку сплайна, по обучающим проходам последней
  эпохи (накопитель сбрасывается в начале каждой эпохи; `eval()`-проходы не
  учитываются)
  (см. [`adapters.md`](adapters.md)); `NaN`, если через адаптер в режиме обучения ещё не
  прошёл ни один батч — в этом случае у `mean`/`max` ещё нет отношения
  к реальным активациям, и они читаются вместе с `NaN` как сигнал
  «сводка снята до прогона данных», а не как надёжное измерение.

## Проверенные инварианты

- Прямая (и постоянная функция как её частный случай) — индекс `0.0`
  (`test_straight_line_has_zero_nonlinearity`,
  `test_identity_has_zero_nonlinearity`,
  `test_constant_function_is_reported_as_linear`).
- Симметричная парабола на симметричном отрезке — индекс `1.0`, прямая не
  объясняет ничего (`test_symmetric_parabola_is_fully_unexplained_by_a_line`).
- Прямая с наложенной осцилляцией — индекс строго между нулём и единицей
  (`test_line_plus_bump_is_between_zero_and_one`).
- `KANLayer` при тождественной инициализации даёт нулевую нелинейность на
  каждом из `in_features * out_features` рёбер
  (`test_identity_layer_shows_no_nonlinearity`).
- Возмущённые коэффициенты сплайна поднимают максимум индекса заметно выше
  нуля (`test_perturbed_layer_shows_nonlinearity`).
- Рёбра идентифицируются полным набором пар `(source, target)`
  (`test_edges_are_identified_by_index`).
- `model_nonlinearity` покрывает все внедрённые KAN-адаптеры (14 = 2 слоя
  x 7 проекций на `tiny_causal_lm`) и на свежевнедрённой, ещё не обученной
  модели даёт нулевое среднее по каждому
  (`test_model_summary_covers_every_kan_adapter`).
- Для `lora`/`dora` сводка — пустой словарь
  (`test_model_summary_is_empty_for_linear_methods`).
- Узкий отрезок измерения даёт не больший индекс нелинейности, чем широкий,
  для одной и той же возмущённой функции — на более коротком отрезке любая
  гладкая функция ближе к своей касательной
  (`test_measurement_interval_is_taken_from_the_caller`).
- `model_nonlinearity` действительно использует переданный `ranges`, а не
  игнорирует его в пользу `observed_range()`
  (`test_model_summary_uses_supplied_ranges`).

- Тождественный `KANLayer` на отрезке `[-3, 3]`, выходящем за сетку, даёт
  индекс `0.0`, а не около 0.81
  (`test_identity_layer_is_linear_even_if_observed_range_exceeds_the_grid`,
  `test_model_summary_ignores_the_part_of_observed_range_outside_the_grid`).
- Область измерения следует за `input_scale` и считается отдельно для каждого
  входа (`test_measurement_domain_follows_input_scale`,
  `test_measurement_domain_is_per_input_feature`).
- Отрезок целиком вне сетки: рёбра не измеряются, сводка — `NaN`
  (`test_range_entirely_outside_the_grid_yields_no_measurement`,
  `test_model_summary_is_nan_when_observed_range_is_outside_the_grid`).
