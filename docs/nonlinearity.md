# Мера выученной нелинейности (`analysis/spline_stats.py`)

**Модуль:** `src/kanlora/analysis/spline_stats.py`
**Тесты:** `tests/analysis/test_spline_stats.py`

## Зачем эта мера нужна

Это не техническая, а исследовательская часть работы. Главный вопрос,
ради которого весь стенд строится: **использует ли KAN-LoRA нелинейность
сплайна на самом деле, и какой ценой** (KAN-LoRA не умеет сливаться с
весами — см. [`adapters.md`](adapters.md) — поэтому нелинейность,
если она не используется, оплачивается задержкой генерации без всякой
пользы).

Измерение прямое: к каждой выученной одномерной функции ребра сплайна
подгоняется прямая методом наименьших квадратов на том отрезке, куда
реально попадают активации, и берётся доля дисперсии, которую эта прямая
не объясняет. Индекс, равный нулю по всем рёбрам всех адаптеров, —
доказанный отрицательный результат («нелинейность не используется, метод
сводится к LoRA с накладными расходами»), а не признак неудачной
реализации.

## `nonlinearity_index`

```python
def nonlinearity_index(inputs: torch.Tensor, outputs: torch.Tensor) -> float
```

Считает

```
index = RSS / TSS,
```

где `TSS` — полная дисперсия `outputs` относительно среднего, а `RSS` —
остаточная сумма квадратов после подгонки прямой `outputs ≈ a * inputs + b`
методом наименьших квадратов (`torch.linalg.lstsq` на паре признаков
`[inputs, 1]`). Значение зажимается в `[0.0, 1.0]`: `0.0` — функция и есть
прямая (или её частный случай — константа), `1.0` — прямая не объясняет
ничего (например, симметричная относительно нуля парабола на симметричном
отрезке, где наилучшая прямая вырождается в константу).

Подгонка и сумма выполняются в `float64` независимо от входного типа —
величина используется как диагностика с претензией на точность, а не как
часть градиентного пути, поэтому дороговизна двойной точности здесь не
имеет значения.

Отдельно обработан вырожденный случай `TSS ≈ 0` (постоянная функция):
вместо деления на ноль возвращается `0.0`, потому что константа — частный
случай прямой, а не неопределённость.

## `layer_nonlinearity` и `EdgeStats`

```python
@dataclass(frozen=True)
class EdgeStats:
    source: int
    target: int
    nonlinearity: float

def layer_nonlinearity(layer: KANLayer, lo: float, hi: float, samples: int = 257) -> list[EdgeStats]
```

`KANLayer` (см. [`adapters.md`](adapters.md)) — это `in_features x
out_features` независимых одномерных функций, по одной на каждое ребро
графа Колмогорова — Арнольда. `layer_nonlinearity` перебирает все рёбра:
для каждого входного индекса `source` подаёт на слой пробный батч, где
координата `source` пробегает равномерную сетку `[lo, hi]` из `samples`
точек, а все остальные координаты — нули, и снимает отклик по каждому
выходному индексу `target`. Обнуление остальных координат не искажает
измерение: базисные функции слоя действуют покоординатно, поэтому отклик
на ребре `(source, target)` не зависит от значений на других входных
координатах.

Отрезок `[lo, hi]` — обязательный внешний параметр, а не константа сетки
сплайна: измерять нужно там, куда реально попадают активации на
отложенном наборе, а не на всей области определения. `model_nonlinearity`
использует `0.99 * grid_range` как первое приближение к этому отрезку (см.
ниже); более точная версия, оценивающая фактический размах входов сплайна
по данным, приходит в Задаче 16 плана вместе с сборкой карточки результата
прогона.

Результат — список `EdgeStats` длиной `in_features * out_features`, без
фиксированного порядка обхода за пределами вложенных циклов по `source`
и `target`; тесты используют его как множество пар `(source, target)`, а
не как последовательность.

## `model_nonlinearity`

```python
def model_nonlinearity(model: torch.nn.Module) -> dict[str, dict[str, float]]
```

Сводка по всей модели, ключ — полное имя адаптера из `adapter_modules`
(`kanlora.adapters.inject`, см. [`adapters.md`](adapters.md)). Не-KAN
адаптеры (`LoRALinear`, `DoRALinear`) в сводку не попадают вообще — у них
нет обучаемой нелинейности, и пустой словарь для чисто линейного метода
(`{}`) — это осмысленный, а не ошибочный ответ.

Для каждого `KANLoRALinear` собирается:

- `mean` — среднее значение `nonlinearity_index` по всем рёбрам слоя;
- `max` — максимум по тем же рёбрам (один вырожденный сплайн не должен
  теряться в усреднении по семи проекциям каждого слоя трансформера);
- `fraction_inside_grid` — `module.last_fraction_inside_grid()`, доля
  активаций последнего прямого прохода, попавших в сетку сплайна
  (см. [`adapters.md`](adapters.md)); `NaN`, если через адаптер ещё не
  прошёл ни один батч — в этом случае у `mean`/`max` ещё нет отношения
  к реальным активациям, и они читаются вместе с `NaN` как сигнал
  «сводка снята до прогона данных», а не как надёжное измерение.

## Проверенные инварианты

- Прямая (и постоянная функция как её частный случай) — индекс `0.0`
  (`test_straight_line_has_zero_nonlinearity`,
  `test_identity_has_zero_nonlinearity`,
  `test_constant_function_is_reported_as_linear`).
- Симметричная парабола на симметричном отрезке — индекс `1.0`, прямая не
  объясняет ничего (`test_symmetric_parabola_is_fully_unexplained_by_a_line`).
- Прямая с наложенной осцилляцией — индекс строго между нулём и единицей
  (`test_line_plus_bump_is_between_zero_and_one`).
- `KANLayer` при тождественной инициализации даёт нулевую нелинейность на
  каждом из `in_features * out_features` рёбер
  (`test_identity_layer_shows_no_nonlinearity`).
- Возмущённые коэффициенты сплайна поднимают максимум индекса заметно выше
  нуля (`test_perturbed_layer_shows_nonlinearity`).
- Рёбра идентифицируются полным набором пар `(source, target)`
  (`test_edges_are_identified_by_index`).
- `model_nonlinearity` покрывает все внедрённые KAN-адаптеры (14 = 2 слоя
  x 7 проекций на `tiny_causal_lm`) и на свежевнедрённой, ещё не обученной
  модели даёт нулевое среднее по каждому
  (`test_model_summary_covers_every_kan_adapter`).
- Для `lora`/`dora` сводка — пустой словарь
  (`test_model_summary_is_empty_for_linear_methods`).

## Не реализовано

Отрезок измерения `[lo, hi]` по фактическому размаху активаций на
отложенном наборе (вместо приближения через `grid_range`), сборка
конфигурации и карточки результата прогона, замер задержки генерации со
слиянием адаптера и без — задачи 16–17 плана, ещё не сделаны.
