# Диагностика окружения

**Модуль:** `scripts/check_environment.py`
**Тесты:** `tests/test_check_environment.py`

## Назначение

Скрипт отвечает на три вопроса, каждый из которых способен сорвать
эксперименты целиком, если обнаружится не сразу:

1. Поддерживает ли установленная сборка PyTorch данную видеокарту. Целевая
   машина — GTX 1080 Ti (архитектура Pascal, `sm_61`, compute capability
   6.1). Свежие сборки PyTorch иногда отказываются от Pascal при компиляции.
2. Есть ли `torch.optim.Muon` в установленной версии PyTorch. Наличие
   проверено вручную на torch 2.14.0 (Muon есть), но в других окружениях
   могло быть иначе, поэтому проверка автоматизирована.
3. Лежат ли на диске файлы наборов данных Spider и PAUQ вместе с файлами
   баз данных SQLite, необходимыми для метрики Execution Accuracy.

Скрипт **не падает исключением** ни при отсутствии CUDA, ни при отсутствии
файлов наборов — он должен давать структурированный отчёт даже в неполном
окружении (например, на машине разработки без GPU и без выкачанных данных).

## Запуск

```bash
python scripts/check_environment.py [--data-root data]
```

`--data-root` задаёт каталог, в котором ожидаются подкаталоги `spider/` и
`pauq/` (по умолчанию `data/`, который игнорируется git — см.
`.gitignore`).

Код возврата: `0`, если все проверки пройдены, `1`, если хотя бы одна не
пройдена. Это позволяет использовать скрипт в CI или как предусловие перед
запуском обучения.

## Структура отчёта

Каждая проверка — экземпляр датакласса `Check(name: str, ok: bool, detail: str)`.
Вывод — построчный список с пометкой `OK`/`НЕТ`, именем проверки и
пояснением, выровненный по ширине самого длинного имени, и итоговая строка
`Пройдено N из M.`

## Проверки

### `check_torch() -> Check`

Всегда `ok=True`; сообщает установленную версию PyTorch. Существует как
единообразная точка входа наравне с остальными проверками, а не как
диагностика риска.

### `check_cuda() -> list[Check]`

- Если `torch.cuda.is_available()` ложно — возвращает один пункт `CUDA`
  с `ok=False` и пояснением «недоступна (ожидаемо на машине разработки)».
  Это ожидаемое состояние на Mac, а не ошибка.
- Если CUDA доступна — возвращает два пункта: `CUDA` (имя устройства и
  архитектура `sm_XY`, `ok=True`) и `поддержка sm_XY в сборке`, которая
  сверяет вычисленную архитектуру со списком `torch.cuda.get_arch_list()`.
  Второй пункт — главный риск проекта: если он вернёт `ok=False` на
  GTX 1080 Ti, обучение на GPU невозможно с текущей сборкой PyTorch.

### `check_muon() -> Check`

Проверяет `hasattr(torch.optim, "Muon")`. При отсутствии сообщает, что
нужна собственная реализация — на момент проверки (2026-09-09, torch
2.14.0) она не нужна, Muon есть в `torch.optim`.

### `check_dataset(name: str, root: Path) -> list[Check]`

Для `name` из `{"spider", "pauq"}` проверяет:

- наличие каждого файла из `DATASET_FILES[name]` по пути `root / filename`;
- наличие хотя бы одного файла `*.sqlite` по маске `root/database/*/*.sqlite`
  (проверка на существование `root` предшествует обращению к `glob`, чтобы
  не падать на отсутствующем каталоге).

Ожидаемая раскладка каталогов:

```
data/spider/
  train_spider.json
  dev.json
  tables.json
  database/<db_id>/<db_id>.sqlite

data/pauq/
  pauq_train.json
  pauq_dev.json
  tables.json
  database/<db_id>/<db_id>.sqlite
```

Имена файлов заданы константой `DATASET_FILES` в самом модуле:

```python
DATASET_FILES = {
    "spider": ("train_spider.json", "dev.json", "tables.json"),
    "pauq": ("pauq_train.json", "pauq_dev.json", "tables.json"),
}
```

Имена файлов PAUQ проверены напрямую по репозиторию
`github.com/ai-spiderweb/pauq` (каталог `dataset/`): реальные файлы —
`pauq_train.json`/`pauq_dev.json`, без префикса `pauq_xsp_`, который
предполагался в первоначальном плане. Раскладка синхронизирована с
загрузчиком `kanlora.data.pauq` (см. `docs/data.md`), включая
`text_field_language="ru"` — то, что `check_environment.py` не проверяет
(его интересует только наличие файлов, а не форма полей внутри них).

## Известные ограничения

- Проверка `check_cuda` при отсутствии CUDA не может подтвердить или
  опровергнуть поддержку `sm_61` — её обязательно нужно прогнать на самой
  GTX 1080 Ti перед началом обучения. Если проверка вернёт `ok=False`,
  единственный обходной путь — откатиться на более старую сборку PyTorch,
  где Pascal ещё поддержан; при этом `torch.optim.Muon` может отсутствовать
  и прогоны с ним придётся снять.
- Отсутствие файлов баз данных PAUQ не считается фатальной ошибкой на
  уровне скрипта (он лишь сообщает `НЕТ`): в этом случае для PAUQ
  предполагается считать только Exact Match, а `execution_accuracy` в
  карточке результата оставлять `null`. Само это решение — методологическое
  и принимается не в этом скрипте.
