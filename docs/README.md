# Техническая документация

Документация описывает фактически реализованное поведение кода в `src/`,
`scripts/` и покрывающие их тесты в `tests/`. Спекулятивные или ещё не
написанные компоненты здесь не описываются — план работ по ним ведётся
локально (`docs/superpowers/plans/`, каталог вне git).

Документы обновляются в рамках той же задачи, в которой меняется описываемое
поведение.

## Состав

- [`environment-check.md`](environment-check.md) — диагностика окружения
  (`scripts/check_environment.py`): поддержка видеокарты, наличие `Muon`,
  проверка файлов наборов данных Spider и PAUQ.
- [`adapters.md`](adapters.md) — B-сплайновый базис, слой Колмогорова —
  Арнольда, общий интерфейс адаптера `AdapterLinear`, реализации LoRA, DoRA
  и KAN-LoRA, и единый внедритель адаптеров в модель (`inject.py`).
- [`data.md`](data.md) — сериализация схемы БД и загрузчики Spider/PAUQ:
  чтение примеров, раскладка файлов наборов, воспроизводимое урезание
  обучающей выборки.
- [`collate.md`](collate.md) — промпт, токенизация и маска функции потерь
  по SQL (`data/collate.py`): рамка промпта, общее для обучения и оценки
  усечение промпта по голове схемы,
  сборка батча с динамическим паддингом.
- [`optimizers.md`](optimizers.md) — AdamW и Muon за единым интерфейсом
  (`train/optimizers.py`): разводка обучаемых параметров по размерности,
  покрытие Muon для LoRA/DoRA/KAN-LoRA, обрезание градиента.
- [`train-loop.md`](train-loop.md) — цикл обучения и замер пиковой
  видеопамяти (`train/loop.py`, `train/memory.py`): накопление градиента,
  чекпоинтинг, логирование доли активаций в сетке для KAN-LoRA, санитарный
  тест на переобучение двадцати примеров и почему он размораживает больше,
  чем только адаптеры, на игрушечной тестовой модели.
- [`generate.md`](generate.md) — пакетная жадная генерация SQL
  (`eval/generate.py`): почему отбор всегда жадный, усечение промпта по
  тому же правилу, что при обучении, дополнение слева,
  обрезание продолжения по первому переводу строки или `;`, и фикстура
  `TinyTokenizer` для тестов генерации без сети.
- [`exact_match.md`](exact_match.md) — обёртка над официальной метрикой
  Spider (`eval/exact_match.py`, вендоренный `third_party/spider_eval/`):
  зачем метрика вендорится без изменений, плоский импорт `evaluation.py`/
  `process_sql.py`, построение схемы базы из `tables.json` без файла
  `.sqlite`, учёт внешних ключей через `rebuild_sql_col`, разбивка по
  сложности запроса.
- [`execution.md`](execution.md) — Execution Accuracy
  (`eval/execution.py`): исполнение SQL на sqlite в режиме только для
  чтения, сравнение результатов вместо текста запроса, роль `ORDER BY`
  эталона в сравнении порядка строк, отступление для PAUQ без файлов баз.
- [`nonlinearity.md`](nonlinearity.md) — мера выученной нелинейности
  (`analysis/spline_stats.py`): подгонка прямой методом наименьших
  квадратов к выученной функции ребра сплайна, доля необъяснённой
  дисперсии как индекс ребра, индекс слоя ΣRSS/ΣTSS (не зависит от
  амплитуды рёбер), сводка по всем KAN-адаптерам модели с отрезком
  измерения по фактическому размаху активаций, пустая сводка для чисто
  линейных методов.
- [`latency.md`](latency.md) — задержка генерации со слиянием адаптера и
  без (`eval/latency.py`): слияние LoRA/DoRA в обычный `nn.Linear` как
  тождественное преобразование, отказ KAN-LoRA сливаться как свойство
  метода, а не недоделка, прогрев и синхронизация CUDA перед замером.
- [`experiment-runner.md`](experiment-runner.md) — конфигурация прогона,
  карточка результата и сквозной скрипт (`config.py`, `results.py`,
  `scripts/run_experiment.py`): неизменяемая `ExperimentConfig`,
  переопределение ключами командной строки, `run_id` для всей матрицы
  экспериментов, базовая модель без адаптера (`method: none`), `null`
  вместо нуля для неизмеренной Execution Accuracy,
  почему `smoke.yaml` и `base.yaml` — одна и та же команда с разными
  размерами.
- [`make-tables.md`](make-tables.md) — сборка итоговых таблиц и графика из
  карточек результатов (`scripts/make_tables.py`): среднее и размах по
  зёрнам вместо одного среднего, отличие «не измерялось» от нуля для
  Execution Accuracy, обязательная строка базового уровня без адаптера
  (из карточек `method: none`), отдельные таблицы по нелинейности и покрытию Muon без
  усреднения по зерну, график доли активаций внутри сетки по эпохам.

## Срез состояния

Документация актуальна по состоянию на коммит `4303788` (ветка `dev`).
Реализованы и описаны все части конвейера: общий интерфейс адаптеров, LoRA,
DoRA, KAN-LoRA и единый внедритель; сериализация схемы БД, чтение
примеров с воспроизводимым урезанием выборки, сборка промпта и маски
функции потерь; разводка обучаемых параметров между AdamW и Muon, цикл
обучения с накоплением градиента, чекпоинтингом и замером пиковой
видеопамяти; пакетная жадная генерация SQL, Exact Match, Execution
Accuracy, индекс выученной нелинейности слоя по всем KAN-адаптерам и
замер задержки генерации без слияния адаптера (в каждом прогоне, поле
`latency` карточки) и со слиянием (LoRA/DoRA; KAN-LoRA отказывается
сливаться в принципе); неизменяемая конфигурация прогона, карточка
результата со временем обучения и скрипт `scripts/run_experiment.py`,
соединяющий все части в одну команду; базовая точка без адаптера
(`method: none`, zero-shot оценка тем же путём); скрипт
`scripts/make_tables.py`, собирающий из карточек основную таблицу со
средним и размахом по зёрнам, таблицы по нелинейности и покрытию Muon и
график доли активаций внутри сетки по эпохам.

Сквозной прогон всех трёх методов и базовой модели проверен на CPU на
наборе Spider (`configs/smoke.yaml`, см. `experiment-runner.md`). Не
выполнено только то, что требует целевой машины: проверка окружения на
GTX 1080 Ti (`scripts/check_environment.py`) и полная матрица
экспериментов на `configs/base.yaml` с замером времени и видеопамяти.
